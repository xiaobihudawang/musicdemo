## 1. 系统简介

音乐分享平台是一个基于 B/S 架构的在线音乐管理系统，支持用户注册登录、音乐上传、在线播放、点赞评论、排行榜查看等功能。平台还集成了 B 站音频下载、AI 智能生成音乐简介等特色功能，为音乐爱好者提供一个便捷的音乐分享与交流平台。

系统采用前后端分离的设计思路，后端基于 Spring Boot 3 + MyBatis + MySQL 8.0 构建，前端采用纯 HTML/CSS/JavaScript 实现，通过 RESTful API 进行数据交互。认证授权采用 JWT + Spring Security 方案，保证系统的安全性和无状态可扩展性。

## 2. 系统开发工具及相关技术介绍

### 2.1 Spring Boot 3

Spring Boot 是 Spring 框架的扩展，提供了自动配置、起步依赖和嵌入式服务器等特性，能够快速搭建生产级别的 Spring 应用。本项目使用 Spring Boot 3.3.6 版本，基于 Jakarta EE 10 标准，实现了 IoC 控制反转、AOP 面向切面编程等核心功能。

### 2.2 MyBatis

MyBatis 是一款优秀的持久层框架，支持自定义 SQL、存储过程和高级映射。相比 JPA/Hibernate，MyBatis 提供了更细粒度的 SQL 控制，适合本项目大量自定义统计查询（排行榜、分组聚合等）的场景。通过 XML 文件集中管理 SQL，便于后期优化和维护。

### 2.3 MySQL 8.0

MySQL 8.0 是一个开源的关系型数据库管理系统，支持 InnoDB 事务引擎、窗口函数、UTF8MB4 完整字符集。本项目中使用了 MySQL 的视图（`v_music_leaderboard`）、存储过程（`sp_batch_delete_user`等）、触发器（计数自动维护）、事件（每日统计快照）和函数（热度分计算）等高级特性。

### 2.4 JWT + Spring Security

JWT（JSON Web Token）是一种无状态的认证方案。服务端签发 Token 后，客户端在后续请求中通过 `Authorization` 头携带 Token，服务端通过签名验证身份。相比传统的 Session 方案，JWT 天然支持水平扩展，不需要共享 Session 存储。

Spring Security 提供了声明式的安全配置，通过 `SecurityFilterChain` 定义 URL 级别的访问规则。本项目配置了无状态会话（STATELESS）和 JWT 认证过滤器，实现了精细化的权限控制。

### 2.5 前端 HTML/CSS/JavaScript

前端采用纯原生技术栈，不使用任何框架。CSS 按"基础→布局→组件→特性"分为四层（`base.css`/`layout.css`/`components.css`/`player.css`），JavaScript 按功能分为工具层（`common.js`）、请求封装层（`api.js`）、业务逻辑层（`pages/*.js`）和启动层（`app.js`）。

### 2.6 BCrypt 加密

BCrypt 是一种密码哈希算法，与传统的 MD5/SHA 不同，它内置了随机盐值（salt），并且可以通过调整 cost 因子控制计算速度（默认 10 轮迭代约 100ms）。这使得暴力破解的成本大幅提高，有效抵抗彩虹表攻击。

### 2.7 DFA 敏感词检测

使用基于 DFA（确定性有限自动机）的敏感词检测库 `sensitive-word` 0.29.3，内置 6 万+敏感词，支持大小写不敏感、全角半角归一化、重复字符识别、中文繁简转换等特性。检测时间复杂度 O(n)，远优于朴素匹配的 O(n×m)。

## 3. 系统分析

### 3.1 可行性分析

**技术可行性**：Spring Boot + MyBatis + MySQL 是成熟的企业级开发组合，社区活跃、文档丰富。纯前端技术栈降低了学习成本。开发工具（IntelliJ IDEA、Maven）均为业界标准。

**经济可行性**：项目所用技术均为开源免费方案（Spring Boot、MySQL Community、Tomcat 等），无需额外授权费用。部署成本低，单台服务器即可运行。

**操作可行性**：Web 界面友好直观，用户无需安装客户端，通过浏览器即可使用。三种角色（游客、普通用户、管理员）的权限划分清晰，操作流程符合日常使用习惯。

### 3.2 功能需求

系统分为三大角色：

| 角色 | 权限 |
|------|------|
| 游客 | 浏览音乐列表、搜索、查看详情、在线播放、查看排行榜 |
| 普通用户 | 游客权限 + 上传音乐、点赞/取消点赞、评论/删除评论、下载音乐、B站下载、AI 生成简介 |
| 管理员 | 用户权限 + 用户管理（启用/禁用/删除）、音乐管理（删除任意音乐）、评论管理（删除任意评论）、封面管理 |

核心功能模块：
- **用户模块**：注册、登录、Token 自动登录、JWT 鉴权
- **音乐模块**：上传、列表/搜索、详情、在线播放（流式）、下载、歌词同步、封面自动抓取
- **互动模块**：点赞/取消点赞、评论/删除评论、敏感词过滤
- **排行模块**：点赞榜 Top10、下载榜 Top10、评论榜 Top10
- **管理模块**：用户列表、启用/禁用、级联删除；音乐列表/删除；评论管理
- **外部集成模块**：B 站音频下载（Python 子进程）、AI 简介生成（DeepSeek API）

### 3.3 非功能需求

- **性能**：列表页 P95 响应时间 < 200ms；播放启动延迟 < 500ms
- **安全**：密码 BCrypt 存储；JWT 签名防篡改；MyBatis `#{}` 预编译防 SQL 注入；`escapeHtml()` 防 XSS
- **可扩展**：JWT 无状态认证支持水平扩展；文件存储路径可配置，可切换为 OSS/MinIO
- **可维护**：Controller → Service → Mapper 三层架构；统一 `Result<T>` 响应格式；全局异常处理

### 4.3 数据库设计

系统共 5 张数据表：

| 表名 | 说明 | 核心字段 |
|------|------|----------|
| `user` | 用户表 | id, username, password, role, enabled |
| `music` | 音乐表 | id, title, artist, file_path, like_count(冗余), comment_count(冗余), download_count(冗余) |
| `comment` | 评论表 | id, content, user_id(FK), music_id(FK ON DELETE CASCADE) |
| `like_record` | 点赞记录表 | id, user_id(FK), music_id(FK), UNIQUE(user_id, music_id) |
| `download_record` | 下载记录表 | id, user_id(FK), music_id(FK) |


**数据库高级特性**：
- **触发器**（7 个）：点赞/评论/下载时自动维护 `music` 表的冗余计数字段，`trg_comment_before_insert` 校验评论内容
- **存储过程**（3 个）：`sp_batch_delete_user` 级联删除用户、`sp_get_leaderboard` 按类型获取排行榜、`sp_recalc_all_counts` 使用游标批量校正计数
- **函数**（1 个）：`fn_music_hot_score` 计算音乐热度分
- **视图**（1 个）：`v_music_leaderboard` 排行榜视图
- **事件**（1 个）：`e_cleanup_old_downloads` 每月自动清理一年前的下载记录

### 4.4 安全设计

1. **密码安全**：BCrypt 加密存储，不可逆
2. **传输安全**：JWT Token 携带在 HTTP Header 中，通过签名防止篡改
3. **SQL 注入防御**：MyBatis `#{}` 参数化查询
4. **XSS 防御**：前端 `escapeHtml()` 转义所有用户输入
5. **权限控制**：Spring Security 基于 URL 和角色的访问控制
6. **双重敏感词检测**：客户端预检 + 服务端 DFA 权威拦截

### 5.3 关键技术实现

**JWT 鉴权流程**：登录成功 → 服务端签发 Token（含 userId/username/role）→ 客户端存 localStorage → 后续请求通过 `Authorization: Bearer xxx` 携带 → JwtAuthFilter 解析并注入 SecurityContext → Controller 通过 Authentication 获取用户信息。

**流式音频播放**：通过 `InputStreamResource` + `ResponseEntity` 返回音频文件，支持 HTTP `Range` 头实现进度拖动。Spring 使用 `StreamUtils.copy` 边读边写，不占用服务端大内存。

**Lyrics LRC 解析与同步**：前端解析 LRC 格式歌词文本，每个 `[mm:ss.ms]` 时间戳对应一行歌词。在 `audio.timeupdate` 事件中根据当前播放时间高亮对应行，滚动到约 40% 位置作为视觉焦点。

**敏感词 DFA 检测**：服务端使用 `sensitive-word` 库构建 DFA 状态树，单次检测时间复杂度 O(n)。客户端单独维护 60+ 常见敏感词做前端预检，减少无效请求。

## 8. 存在的问题及建议

1. **并发支持**：当前系统未做读写分离和缓存优化，高并发场景下数据库可能成为瓶颈。建议引入 Redis 缓存热门数据。

2. **文件存储**：当前音频文件存储在本地磁盘，不适合分布式部署。建议接入对象存储服务（OSS/MinIO）。

3. **AI 生成速度**：AI 简介生成为同步调用，用户体验不佳。建议改为异步队列处理，上传完成后先返回，AI 生成后自动回填。

4. **搜索能力**：当前基于 MySQL LIKE 模糊查询，大数量下性能下降。建议引入 Elasticsearch 实现全文搜索。
