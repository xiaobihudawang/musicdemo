## 第一梯队：核心架构（必须会，必问）

### 1. JWT 认证流程

**看的文件：**
- `config/JwtUtils.java` — Token 生成（subject=userId）、解析、验证
- `config/JwtAuthenticationFilter.java` — 每个请求的认证处理
- `config/SecurityConfig.java` — URL 权限规则

**关键流程：**
```
请求 → JwtAuthenticationFilter.doFilterInternal()
     → extractToken() 从 Authorization 头取 "Bearer xxx"
     → jwtUtils.validateToken(token) 验证签名+过期
     → Claims 解析出 userId / username / role
     → userMapper.findById(userId) 检查用户是否被禁用
     → 设置 SecurityContextHolder（全局认证信息）
     → filterChain.doFilter() 放行
```

**能说清：**

| 问题 | 答案 |
|------|------|
| 为什么用 STATELESS？ | 无状态，水平扩展不需要 session 同步 |
| 验证步骤？ | ① 签名验证 ② 过期检查 ③ DB 查用户是否启用 |
| role 怎么映射？ | DB 存 `'admin'`/`'user'`，Filter 里 `ROLE_` + `toUpperCase()` |
| 如果用户被管理员禁用？ | Filter 中 `user.getEnabled()` 为 false 时不设认证信息，请求被拦截 |

### 2. 反范式设计 + 触发器

**看的文件：** `schema.sql`（触发器部分）

**要点：**
- music 表有 `like_count`/`comment_count`/`download_count` 三个冗余字段
- 7 个触发器维护一致性：

| 触发器 | 事件 | 动作 |
|--------|:----:|------|
| `trg_like_insert` | like_record INSERT | music.like_count + 1 |
| `trg_like_delete` | like_record DELETE | music.like_count - 1 |
| `trg_comment_before_insert` | comment BEFORE INSERT | 校验 content 非空且 ≤ 2000 |
| `trg_comment_insert` | comment INSERT | music.comment_count + 1 |
| `trg_comment_delete` | comment DELETE | music.comment_count - 1 |
| `trg_download_insert` | download_record INSERT | music.download_count + 1 |
| `trg_download_delete` | download_record DELETE | music.download_count - 1 |

**能说清：**
- 为什么用反范式？→ 排行榜高频查询，每次 `COUNT(*) JOIN` 大表下性能差。空间换时间。
- 一致性怎么保证？→ 触发器在 INSERT/DELETE 关联记录时自动维护，业务层也加 `@Transactional`。
- 数据不一致如何修复？→ `sp_recalc_all_counts` 用游标遍历所有音乐重新统计。

## 第二梯队：关键业务流程（很可能问）

### 4. 流式播放

**看的文件：** `MusicController.stream()`

```java
@GetMapping("/{id}/stream")
public ResponseEntity<InputStreamResource> stream(@PathVariable Integer id) {
    Music music = musicService.findById(id);
    File file = new File(music.getFilePath());
    InputStreamResource resource = new InputStreamResource(new FileInputStream(file));
    return ResponseEntity.ok()
            .contentType(MediaType.APPLICATION_OCTET_STREAM)
            .body(resource);
}
```

**能说清：**
- `InputStreamResource` 包装文件流，Spring 用 `StreamUtils.copy` **边读边写**，不加载整个文件到内存
- 支持 HTTP `Range` 头 → 浏览器/播放器可实现拖动进度条
- 音频文件路径通过 `WebConfig` 映射到本地磁盘

### 5. 点赞功能

**看的文件：** `LikeController.toggleLike()` + `LikeService.toggle()`

```java
@Transactional
public boolean toggle(Integer userId, Integer musicId) {
    LikeRecord existing = likeRecordMapper.findByUserAndMusic(userId, musicId);
    if (existing != null) {
        likeRecordMapper.delete(userId, musicId);  // 取消点赞
        return false;
    } else {
        LikeRecord record = new LikeRecord();
        record.setUserId(userId);
        record.setMusicId(musicId);
        likeRecordMapper.insert(record);            // 点赞
        return true;
    }
}
```

**能说清：**
- 幂等设计：已赞→取消，未赞→点赞
- 触发器自动维护 `music.like_count`（无需手动写 UPDATE）
- `@Transactional` 保证事务（虽然单条 SQL 不需事务，但体现规范）

### 6. 排行榜查询

**看的文件：** `RankingController` + `MusicMapper.xml`

```
周榜实现逻辑：
1. 计算最近 7 天的日期范围
2. 从 like_record / download_record / comment 按 music_id GROUP BY
3. 统计 COUNT 后取 TOP 10
4. 关联 music 表获取标题/歌手/封面
```

**能说清：**
- 三种排行：点赞榜、下载榜、评论榜
- 为什么冗余字段还要 JOIN 历史表？→ 周榜统计的是**本周新增**，不是总量；冗余字段是**全量累计**

### 8. 敏感词过滤

**看的文件：** `SensitiveWordService`

**能说清：**
- 算法：DFA（确定性有限自动机），时间复杂度 O(n)——只遍历一遍文本
- 内置 6 万+ 敏感词，支持繁简转换、全角半角归一化、重复字符归一化（如 "你 妈 的" → "你妈的"）
- 客户端预检 60+ 常见词，快速拦截减少无效请求
- 服务端 `@PostConstruct` 单例初始化，生产可改读数据库动态加载

### 11. BCrypt 加密

**看的文件：** `SecurityConfig.java` 的 `passwordEncoder()` Bean

**能说清：**
- 为什么用 BCrypt？
  - 自动加盐（每次加密结果不同）
  - 可调计算成本（`strength` 参数控制迭代次数）
  - 抗彩虹表攻击
- 为什么不用 MD5/SHA？→ 计算快，容易被暴力破解
- 密码校验：`BCryptPasswordEncoder.matches(raw, encoded)` → BCrypt 自己从 encoded 中提取盐值

### 13. 歌词同步

**看的文件：** `detail.js`

```
流程：
1. loadLyrics() 请求 GET /api/music/{id}/lyrics
2. parseLRC() 解析 [mm:ss.xx] 格式 → [{time: 秒数, text: "歌词"}]
3. renderLyrics() 生成 DOM 元素
4. audio.timeupdate 事件（每 250ms 触发）
5. 倒序查找 currentTime 对应的歌词行索引
6. 切换 active/passed CSS 类
7. scrollIntoView 使当前行保持在 40% 高度位置
```

**能说清：**
- LRC 格式：`[00:12.34]歌词内容`
- 倒序查找：从最后一行往前找，找到第一个 `time ≤ currentTime` 的，比正序遍历效率高

### 16. 异常处理模式

```
Service 层： throw new RuntimeException("错误描述")
Controller 层：
    try {
        service.doSomething();
        return Result.success(data);
    } catch (Exception e) {
        return Result.fail(e.getMessage());
```

所有 API 返回统一格式：

### 18. 外部进程集成

**看的文件：** `BilibiliService` / `AiService`

```
Java (ProcessBuilder) → 启动 Python 子进程 → stdout 输出 RESULT:{...JSON...} → Java 读取
```

**能说清：**
- 每请求一进程：避免状态污染，进程退出即回收
- 约定协议：Python 端输出 `RESULT: {...JSON...}` 表示成功
- 超时控制：30 秒 `waitFor` 后强制 `destroyForcibly`
- 故障隔离：子进程崩了不影响 Spring Boot 主进程
